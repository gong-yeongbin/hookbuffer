# Product

## Platform

web

## Users

국내 소규모 팀·1인 개발자의 백엔드 개발자. 결제(토스페이먼츠·포트원)·커머스·메신저·GitHub 등의 웹훅을
자기 서버로 직접 받다가 배포·장애 중 유실, 느린 응답으로 실패 처리, 폭주로 서버 다운을 겪은 사람.
주 작업은 운영 중 "무슨 일이 있었나"를 보고(이벤트·전달·시도 기록) 실패한 것을 다시 보내는 것.
데스크톱에서 쓴다(최소 폭 1024px). UI 언어는 한국어.

## Product Purpose

외부 서비스가 보내는 웹훅을 대신 받아 저장하고, 수신 서버가 준비될 때까지 재시도하며 전달하고,
전부 기록으로 남겨 다시 보낼 수 있게 하는 웹훅 수신 게이트웨이. 성공은 "웹훅이 사라지지 않았고,
무슨 일이 있었는지 볼 수 있고, 다시 보낼 수 있다"는 것.
1차 목적은 포트폴리오, 2차가 사이드 수익(2026-09 결정).

## Positioning

범용으로는 Hookdeck·Svix·Convoy와 가격 경쟁이 불가능하다. 국내 특화로 좁힌다: 국내 웹훅(토스페이먼츠·포트원 등)의
서명 설정 예시와 한국어 문서. 업체별 서명 프리셋은 두지 않고 범용 서명 설정 하나만 제공한다(2026-10-01 결정).
Hookdeck을 기능·요금의 기준점으로 삼는다.

## Operating Context

- 흐름: 발신자 → `POST /in/:slug`(소스 URL) → 서명 검증·멱등 → 저장 → 연결된 목적지마다 전달(delivery) → 재시도 → 기록.
- 용어: 소스(source, 받는 주소) · 목적지(destination, 보낼 주소) · 연결(connection, 소스→목적지, 재시도 설정 소유) ·
  이벤트(event, 받은 웹훅 1건) · 전달(delivery, 목적지 하나로의 전달) · 시도(attempt) · 거부된 요청(rejected request) ·
  리플레이(replay, 새 이벤트로 다시 보냄).
- 전달 상태: pending(대기) · succeeded(성공) · failed(재시도 대기) · dead(실패) · canceled(취소) · held(보류).
- 조직(organization) 아래 프로젝트(project) 여러 개. 소스·목적지·이벤트는 프로젝트에 속하고, 역할(owner/admin/member)과 요금은 조직 단위.
- 대시보드 화면(사이드바 순서): 이벤트 · 전달 · 연결 · 소스 · 목적지 · 설정. 계정 메뉴: 사용량 · 조직 설정 · 로그아웃.
- 공개 화면: 랜딩 `/`, 요금 `/pricing`, 로그인 `/login`(구글), 개발자·문서(준비 중).

## Capabilities and Constraints

- 받는 방식 POST·PUT·PATCH·DELETE. 2xx만 성공, 나머지는 재시도. 기본 재시도 2배씩·5분·9회, 최대 50회 또는 1주일. `Retry-After` 우선.
- 목적지 보호: 동시성 제한, 서킷 브레이커(5회 실패 → 60초 열림). 내부망 주소 차단.
- 요금(2026-10 확정, 화면에 표시 중): Free 0원 — 월 1,000 이벤트·초과 시 거부·멤버 1·프로젝트 1·소스·목적지 각 3·보존 3일.
  Team 49,000원 — 월 10,000 이벤트·초과 10만 건당 10,000원부터·무제한·보존 7일. Business는 화면에서 뺐다. 결제는 준비 중(토스 미발급).
- 이벤트 1건 = 받아서 저장한 웹훅 1건. 목적지 수·재시도는 세지 않고, 리플레이는 새로 센다.
- 데스크톱 전용. 모바일 대응 없음. 상태는 서버 상태와 URL만(전역 스토어 없음).
- MVP 제외: 필터·변환, CLI 터널, 알림 채널, 발신 웹훅, 구글 외 로그인, 연간 결제.

## Brand Commitments

- 이름 **hookbuffer**. 로고·마크는 없다.
- 글꼴 Pretendard와 기존 청록 강조색은 고정이 아니다. 이번 재설계에서 바꿀 수 있다.
- 미결: 백엔드가 목적지에 붙이는 헤더 접두사 `X-Hookbuffer-*`와 저장소·패키지 이름은 API 계약·인프라라 별도 결정. 화면·문서의 이름만 먼저 바꾼다.

## Evidence on Hand

- 실제 고객·후기·처리량 수치는 없다. 만들어 넣지 않는다.
- 증거는 "어떻게 만들었나": 아키텍처(API·워커 분리, Valkey Stream, 아웃박스 sweeper), 재시도·보류·서킷 정책,
  `docs/webhook-gateway/plan.md`·`context-notes.md`(로컬 전용 문서). 랜딩에는 수신→저장→재시도 전달 흐름 그림이 있다
  (`src/pages/landing/FlowDiagram.tsx`).
- 요금 수치는 `src/pages/pricing/PricingPage.tsx`가 원본.

## Product Principles

- 무슨 일이 있었는지 숨기지 않는다. 받은 것·보낸 것·실패한 이유를 그대로 보여 준다.
- 운영 화면은 표와 상세가 중심이다. 빠르게 훑고, 한 건을 깊게 본다.
- 과장하지 않는다. 없는 고객·수치를 만들지 않고, 준비 중인 것은 준비 중이라고 쓴다.
- 국내 개발자가 한국어로 막힘 없이 쓴다. 외래 용어는 영문 상태값(pending 등)과 한국어 라벨을 함께 둔다.
- Hookdeck이 기준점이다. 다르게 할 때는 이유가 있어야 한다.

## Accessibility & Inclusion

- 상태를 색만으로 구분하지 않는다(라벨을 함께 쓴다). 움직임 줄이기 설정을 존중한다. 정해진 외부 표준은 없다.
